# Agent guide: ENGR 321 drone dashboard study

Teammates' AI agents use this repo to upload study data, keep it organized, and rebuild the report. Read this whole file before changing anything.

## The one rule: this repository is PUBLIC

Anything pushed is public and stays in git history. Never commit, paste, or upload:

- names, emails, student IDs, or anything that links a person to a participant ID (only coded IDs like `P001`)
- face or screen videos (`*.webm`, `*.mp4`): they stay on the team's password-protected drive
- Apple Health exports (`export.zip`, `export.xml`): read them in place, never copy them into the repo
- consent forms or scans of them

If you are unsure whether something is identifying, don't commit it; ask your user. If something private was already pushed, stop and tell your user right away: removing it takes history rewriting, which they must approve.

## First time in a clone

```bash
git config core.hooksPath .githooks
```

This turns on the pre-commit hook that blocks videos, health exports, consent files, and data that fails validation.

## Uploading a participant's data

The simulator (`simulation/drone_sim.html`) downloads files named `P001_S1_Nimbus_Trial1_20261112_summary.csv` and similar into the browser's Downloads folder. Always go through `tools/ingest.py`; never copy files into `data/` by hand.

1. `git pull --rebase origin main`
2. `python tools/ingest.py add <folder with the sim downloads> --dry-run`, then show your user what will be added.
3. `python tools/ingest.py add <folder>`. It copies only valid sim CSVs into `data/raw/<ParticipantID>/`, leaves out videos and health exports, and refuses anything whose participant ID isn't coded (for example a name typed into the sim). Don't work around a refusal: report it to your user.
4. Heart rate, either way:
   - from the Apple Health export: `python tools/ingest.py hr P003 --apple-health <path to export.zip>` (upload that participant's events CSVs first; it uses their start and end times)
   - or typed in: `python tools/ingest.py hr P003 --baseline 72 --nimbus 88 --aerodash 95`
5. `python tools/ingest.py check` must pass, then `python tools/ingest.py status` shows what each participant still needs.
6. Commit only `data/raw/<ParticipantID>/...`, with a message like `Add P003 session data`, then `git pull --rebase origin main` and `git push origin main`.

Each participant has their own folder, so several teammates can upload at once without conflicts. If a push is rejected, pull with rebase and push again.

## The report

- `report/template.md` is the source: prose, structure, and `{{placeholders}}` for numbers, tables, and figures.
- `report/REPORT.md`, `report/figures/`, and `report/results/` are **generated by GitHub Actions** on every push to `main` that touches data, analysis, tools, or the template. Never edit or commit them; the hook blocks it.
- To preview locally: `pip install -r requirements.txt`, then `python tools/build_report.py`. This writes to `build/`, which is git-ignored.
- To change wording, add a section, or fill a `[TO COMPLETE]`, edit `report/template.md`. Write numbers through placeholders, never typed in, so they stay correct as data arrives. A new placeholder needs a matching entry in `values` in `tools/build_report.py`.
- The report follows IEEE conference style: Roman-numeral sections, `TABLE I.` captions above tables, `Fig. 1.` captions below figures, and numbered references cited as `[1]` in order of first use.
- Interpretation (Discussion, Conclusion) is for the team to write. Draft it if asked, but don't state a finding the generated results don't support, and recheck it after new data arrives.

## Analysis

`analysis/analyze.py` reads every `*_summary.csv`, `*_survey.csv`, and `*_heart_rate.csv` under `data/raw/` and runs two-tailed paired t-tests (Nimbus minus AeroDash), matching the `5_Stats` tab of `analysis/Project2_Analysis_Workbook.xlsx`. Practice runs are ignored. If you change a calculation, keep it matching the workbook, or explain the difference in the commit message and the report's Analysis section.

## Layout

| Path | What | Who edits |
| --- | --- | --- |
| `simulation/` | The simulator, a single offline HTML file | Team, via pull request |
| `data/raw/<PID>/` | Sim CSVs and `<PID>_heart_rate.csv` | `tools/ingest.py` only |
| `data/session_schedule.csv` | Counterbalancing plan (matches what the sim assigns) | Team |
| `analysis/` | Workbook template and `analyze.py` | Team, via pull request |
| `tools/` | `ingest.py` (upload and checks), `build_report.py` | Team, via pull request |
| `report/template.md` | Report source | Team and agents |
| `report/REPORT.md`, `report/figures/`, `report/results/` | Generated report | GitHub Actions only |
